# SDR-005 | ShanghaiTech 上的端点对齐状态复用

## 研究范围与先例

从 PR #6 的 748b2f949685d235d886a8b1acc9742aa190db7f 开始。SDR-004 保留 44 通过、1 跳过、48 次完成的训练、30,720 次更新及 576 条可复算 IoU。上一轮 LAST-d4 的 ID/U/分支 IoU 为 .5461/.3474/.5368，原 SST 为 .5071/.3264/.5326，强特征 L6 为 .6255/.4355/.6697，全图 L7 为 .8410/.5976/.6300。上一轮科学门失败。本轮用真实数据比较同物理端点的状态交接，冻结 LAST 和 BCST。

Arcee 已公开可微的视觉 Mamba 末态到下一块初态交接，MambaVLT 也在视频帧间复用内部末态。EASR 作为**已知机制的端点约束比较**，只检验同一图像共享四轴外轮的反向同端点映射。VMambaCC 已将视觉 Mamba 用于人群计数。已查工作及重合范围单列。[SDR-004](../SDR-004/REPORT.md) · [本轮指令](https://github.com/xinnan369/sdr-mamba/issues/7) · [Arcee](https://arxiv.org/html/2511.11243) · [文献核查](literature_gap.md)

## 真实数据、标注和共同模型

读取相关本地人群计数项目已配置的 ShanghaiTech Part B，核实 400 个原训练图像/点对及 316 个原测试对。按有效 head count 排序，相邻 20 张为一层，每层取 3 张由种子控制的验证图，得到 340/60/316 图。哈希检查确认三个分割没有相同图像字节。数据和标注原件保留本地，只发布匿名键、汇总计数、哈希及不含点坐标的评估证据。用 0-based `[x,y]` 与半开图像范围，核实 MATLAB 点数元数据，拒绝非有限和坏格式。有限越界坐标按已有项目约定丢弃，训练/验证/测试分别丢弃 119 / 10 / 87 个，空标注为 0。所有图原尺寸 1024×768。[原始论文](https://www.cv-foundation.org/openaccess/content_cvpr_2016/papers/Zhang_Single-Image_Crowd_Counting_CVPR_2016_paper.pdf) · [官方数据页](https://github.com/desenzhou/ShanghaiTechDataset) · [审计](data_audit.json) · [匿名分割清单](split_manifest.json)

训练原分辨率均匀随机 crop 256×256、半概率水平翻转，不缩放。坐标分到 stride-8 的单元后以点数赋质量。训练密度用边缘重归一化的 3×3 二项核平滑，确保非负且和等于有效点数。验证采用未平滑的质量格点用于 GAME 和密度图 MAE，按完整原图一次前向、不切片和不重复计数。GAME(1–3) 用 2×2、4×4、8×8 原图格子，并与 stride 对齐。模型读入实际尺寸；有 padding 的接口先按有效尺寸切分，再按相同形状分组，pad 值从未进入 CNN 或 SSD 控制状态。裁剪分出排除的点数并做全组账本比对。

本地 ImageNet ResNet18 缓存未通过官方哈希前缀核对。各组共同用随机初始化 stride-8 三层 CNN、64 通道特征和非负 softplus 密度头。各组用同一分块 FP32 oracle、4 头×16、d_state=8、T=4 训练。若当前方向同一物理行列的起点等于反向扫描的终点，C3 在下一轮以 0.5 倍反向末态作初值。C2 用同方向末态，C4 在合法同轴源线中固定索引偏移 +1，均只读取上一轮状态。C5 用匹配物理端点的读出尾 token 按距离起点的顺序重新排列后注入 x 前缀，短于 8 token 时补齐未使用量；内部初态 reset。C3 的同轴、同端点映射不增加扫描次数和包容量。四方向输出逆序后逐像素平均。

| 模式 | 定义 |
|---|---|
| C0 | 共同 CNN 和密度头，无 mixer |
| C1 | 全图独立行/列，4 轮共享 reset |
| C2 | 同方向携带真实内部末态 |
| C3 | 反方向、同物理端点携带真实内部末态 |
| C4 | 反向、固定错配物理线的真实末态 |
| C5 | 反向同端点、等 payload 特征消息，内部 reset |
| C6 | 每轮独立参数的全图轴向 reset |

训练 32×32 特征轴各长 32，验证长度 128/96。每图每轮 token 访问分别为 4,096 和 49,152；四轮 1,000 更新、batch=2 的 mixer 每组 32,768,000 token。每轮完整图的状态银行有 448 条方向线，每线 4×16×8 FP32，共 917,504 字节；训练每图为 262,144 字节。C5 等传输负载、注入位置和数值不同。固定共享 chunk=16，两个密集 matmul 每块约 264,192 FLOPs，完整图约 0.812 G/轮，训练 crop 约 0.068 G/轮，尚未计入 CNN、投影、非线性和运存访问。分块之间不 detach，不创建全长核。该实现是研究用 Mamba-2 风格 SSD core。

## 工程证据与统一训练

WSL2 检到 3090、93 GiB 可用空间和 nvcc 11.5。官方固定版本 v2.2.4 的源码需要 ≥11.6，且两套环境没有已批准的完整依赖。官方环境安装 BLOCKED，FP32/BF16 官方 parity 为 NOT_RUN。原生 CUDA chunk 回退通过显式递推对照。CPU FP64/FP32 检查分组、短/非整块尾段、输出、末态及两轮反传；CUDA FP32 在长度 9/37/96/128 的输入上最大前向/末态差约 2.98e−8/4.47e−8，含第二轮的操作数梯度最大差 1.08e−6。在 N=2 的小算子测试中，长度 9/37/96/128 平均约 1.93/6.30/11.67/13.62 ms，增量峰值分配约 26/56/64/68 kB，含并发后台工作负载。第一次 CUDA 工具探测因测试模块导入路径失败，原日志保留；用 runpy 重跑。CPU 最终 53 项通过，3 项条件跳过。[环境与安装](installation_log.md) · [CPU 日志](test_log.txt) · [官方条件测试](gpu_official_parity_log.txt) · [CUDA 自定义校验](gpu_chunked_parity_log.txt)

两次早期真实图 sanity 检验都在正式筛选之前。v1 的报告门曾因仅看 MAE 相对初值下降而显示 PASS，实测最终 MAE 2.67 等于全零基线，手工拒绝。v2 均衡前景 L1 后，最后点 crop MAE 2.53 高于初值 2.18，门失败。v3 在多个人数分位的六张训练图固定中心附近真实点 crop，注册质量保持平滑、缩小残差初始化、共同梯度裁剪和计数目标再重跑。160 更新后损失 2.2823→1.1093，crop MAE 23.51→12.49，低于全零基线 33.17。中间 80 步的 MAE 更低仍遵守最后 checkpoint；固定 crop 结果只说明方法能学习这六个样本。[v1 退化](sanity_v1_degenerate/sanity_log.txt) · [v2 失败](sanity_v2_failed/sanity_log.txt) · [v3 检验](sanity_log.txt)

正式配方为 64×密度加权 MSE（每格权重为 1+8×目标质量），加 0.25×log1p 全图质量的 smooth L1（β=.2）。AdamW 恒定学习率 0.0005、梯度范数裁剪 1、batch 2，每组固定 1,000 更新，种子 0；所有组共享裁剪/翻转顺序和最后 checkpoint。每 100 更新记录训练段均值与验证误差。单组上限 7,200 秒，整轮 86,400 秒。独立分片避免写同一日志，汇总时校验分割与 checkpoint。验证比较 C1 相对 C0 容差 5%，共同训练段损失下降至少 5%，C3 对 C1/C2/C4 各至少相对降低 MAE 2%，GAME1 回退不超过 2%；至少一项当轮干预对单图平均绝对计数和密度 L1 分别达到 .10/.25。仅通过后才加两个种子并一次性测官方测试。[最终配置](../../configs/sdr005.json) · [训练曲线](train_curves.csv) · [裁剪账本](crop_ledger.csv)

### 深度、偏差与典型样本

共享重置 C1 在 T=1/2/4/6/8 的 MAE 是 100.57/118.88/105.82/95.23/89.61。C3 同深度误差为 93.26/58.40/51.46/95.52/180.83，T=6/8 深度外推的偏差升至 +72.28/+171.01。C4 在 T=2/4/6/8 保持约 47 MAE。共享 reset 有参数节省，C1 用 33,405 个参数，较等 token 的非共享 C6 的 62,673 个少 46.7%。本预算下 C1 的主 MAE、空间误差和偏差都比 C6 高，简单 CNN 的 C0 也表现更好，缺乏共享 reset 在本任务的实测精度和参数效率证据。[深度记录](depth_metrics.csv) · [运行账本](runs.csv)

C3 的 +0.74 总体偏差掩盖低、中人数高估和高人数低估。例如 [50,100) 桶 16 图平均高估 40.22，[200,+∞) 桶 11 图平均低估 108.49。与 C4 相比，C3 在高人数桶 MAE 从 136.62 降至 121.64，低于 100 人的三个桶 MAE 都增加。C5 在最高人数桶的 MAE 为 90.69、GAME1 为 107.44，对应 C3 为 121.64 和 155.74。C3 的 GAME1–3 与密度单元 MAE 输给 C2、C4，整体计数偏差接近零与局部精度提升没有同步出现。[分桶](density_bins.csv)

### 状态干预

固定 C3 的第 4 轮输入特征和第 3 轮 bank，干预只改变该轮起始状态。每图先对密度差求和后取绝对值得到绝对计数差，对密度差逐单元取绝对值再求和得到密度 L1。

| 干预 | 平均绝对计数差 | 平均密度 L1 |
|---|---:|---:|
| 当轮清零 | 4.605 | 6.584 |
| 当轮同向 | 0.223 | 1.526 |
| 当轮错线 | 0.160 | 2.165 |
| 全轨迹清零 | 18.955 | 24.476 |

三个当轮干预均超过计数和密度阈值。全轨迹效应更大，包含此前轮次导致的特征变化。第 4 轮各方向在距起点 0–7 token 的平均初态保留为 .760–.932，在 64+ 为 .096–.161；对应初态读出与总 SSD 读出的 L2 比从 .790–1.491 减到 .106–.181。该范数比可超过 1，因为总读出含有可与初态贡献抵消的输入及跳连项。状态能改变预测并随距离衰减，错线和同向的训练对照仍给出更低的计数及空间误差。[干预账本](intervention.csv) · [距离诊断](retention.csv)

## 复现

在仓库根目录使用现有隔离依赖环境。将 `SDR005_DATA_ROOT` 设置为已获授权、含 `train_data` 与 `test_data` 的 Part B 本地目录，`SDR005_PYTHON` 指向现有 CUDA Python。每次使用新的输出目录。模型图像、点标注和 checkpoint 均在本地生成或读取，仓库提供运行账本和校验和。日志中的个人绝对路径已替换为通用占位符。

```powershell
$env:PYTHONPATH = "src"
$env:PYTHONUTF8 = "1"
$env:CUBLAS_WORKSPACE_CONFIG = ":4096:8"
$sdrPython = $env:SDR005_PYTHON
$sdrOutput = "runs/sdr005-repro"
& $sdrPython -m pytest -ra -s
& $sdrPython -m scripts.train_sdr005 --phase audit --device cuda --output $sdrOutput
& $sdrPython -m scripts.train_sdr005 --phase overfit --device cuda --output $sdrOutput
& $sdrPython -m scripts.screen_sdr005 --output $sdrOutput --shards "runs/sdr005-repro-shards" --python $sdrPython
& $sdrPython -m scripts.eval_sdr005 --phase validation --device cuda --output $sdrOutput
if ((Get-Content "$sdrOutput/validation_gate.json" -Raw | ConvertFrom-Json).status -eq "PASS") {
    & $sdrPython -m scripts.train_sdr005 --phase pilot --device cuda --output $sdrOutput
    if ($LASTEXITCODE -eq 0) {
        & $sdrPython -m scripts.eval_sdr005 --phase test --device cuda --output $sdrOutput
    }
}
& $sdrPython -m scripts.profile_sdr005 --output $sdrOutput
& $sdrPython -m scripts.summarize_sdr005 $sdrOutput
```

配方的历史注册点为 `6721aa2`、`5fa1911` 和最终 `3ec4f1d`。发布证据记录正式筛选/验证的完整训练提交、配置哈希、数据哈希、checkpoint 哈希与原始日志。[运行账本](runs.csv) · [环境](environment.txt) · [验证溯源](validation_evaluation_started.json)
